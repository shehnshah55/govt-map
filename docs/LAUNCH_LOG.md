## 2026-09-26 · Phase 0: Baseline

Branch `launch/phase-0-baseline`, from `main` at `8f8fb5d`.

### Gates on a clean checkout

A fresh clone of `main` (`8f8fb5d`), Node 22.22.2, npm 10.9.7, `npm ci`:

| Gate | Result |
|---|---|
| `npm run validate` | pass: 785 organizations, 1,791 positions, 134 people, 1,141 jurisdictions, 149 laws, 6,034 edges, 0 warnings |
| `npm test` | pass: 25 tests |
| `npm run typecheck` | **fail**: `src/main.ts` imports `public/data/graph.json`, which is generated and gitignored, so `tsc` can't resolve it on a clean checkout. CI never ran this gate, so the failure went unnoticed |
| `npm run build` | pass (it runs `npm run data` before `tsc`) |

Fix: `typecheck` now runs `npm run data` first, as `build` already did, and CI runs `typecheck` as its own step.

### What changed

- `scripts/audit-coverage.ts` and `npm run audit:coverage`. It writes `docs/COVERAGE.md` and the README's "At a glance" block from the data.
  - Its output depends only on the data: record ages are measured from the latest date in the data, not from the clock.
  - `npm run audit:coverage -- --check` fails if either file is out of date. CI runs it.
- Organisations generated by the build (division and district offices) are now marked `generated: true`, like generated posts, so authored and generated records can be counted separately.
- README:
  - "At a glance" is now generated and separates authored from generated records.
  - It adds "posts with a known current holder", "legislative seats with a named member" and the data date range.
  - The "compiled up to late 2025" sentence is replaced.
- `docs/DATA_MODEL.md` documents `legal_cases` and the `generated` flag on organisations.
- Tests for the audit: deterministic output and the source-level classification.
