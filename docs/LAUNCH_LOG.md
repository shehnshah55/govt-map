## 2026-10-02 · Phase 1: Security hardening

Branch `launch/phase-1-security`, stacked on `launch/home-pm-office-map` (PR #4) at `1c4b3af`. No network access was needed; no data changed.

### What changed

- **URLs from the data:**
  - `src/lib/safe-url.ts` holds one rule: `https:` only (`http:` only for hosts in an allowlist, empty today). It rejects `javascript:`, `data:`, `vbscript:`, mixed-case and whitespace variants, and URLs with credentials.
  - `Source.url`, `Organization.website` and `Law.url` use it in the schema. The asset CSV check in `compile.ts` uses it too.
  - All data URLs already met the rule.
  - Views also wrap every data URL in `safeHref()`, and every external link has `rel="noopener noreferrer"`.
- **`raw()` audit:**
  - Party colours must be `#rrggbb` (they go into SVG attributes and inline styles).
  - The hemicycle and search suggestions now escape their hand-built attributes.
  - Each remaining dynamic `raw()` says why it is safe.
- **Escaping test:** `tests/security.test.ts` injects `<script>`, `"><img onerror>`, `<svg onload>` and `javascript:` URLs into every text and URL field. It then renders every page type, more than 1,000 pages, and scans the markup for real tags, `on*` attributes and dangerous URLs.
  - Checked that it fails when a single `safeHref()` or `esc()` is removed.
- **Content-Security-Policy:** a `<meta>` in `index.html`: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; base-uri 'self'; form-action 'none'; object-src 'none'`.
  - The single-file build gets its own policy from `vite.config.ts`: its inline script is allowed by SHA-256 hash, never `'unsafe-inline'`, and its inlined fonts by `data:`.
  - **Deviation from §3.1:** `frame-ancestors 'none'` is left out. Browsers ignore it in a `<meta>` tag and log an error, so it only works as an HTTP header, which GitHub Pages can't set.
  - `object-src 'none'` and a referrer policy were added.
- **Fonts:** self-hosted from the Fontsource npm packages (SIL OFL 1.1), replacing Google Fonts. Only the weights and subsets in use are loaded, woff2 only, about 380 KB in total. The Urdu font is the Arabic-script subset of Noto Nastaliq Urdu, weight 400 only (the only weight the site uses).
  - **New dependencies:** `@fontsource/ibm-plex-sans`, `@fontsource/ibm-plex-mono`, `@fontsource/noto-nastaliq-urdu` and `@fontsource-variable/source-serif-4`. They are needed so the site makes no runtime call to a font CDN (§0.4).
- **Build check:** `npm run check:build` (`scripts/check-build.ts`) fails if a built page:
  - lacks the CSP;
  - allows `'unsafe-inline'`, `'unsafe-eval'` or a wildcard for scripts;
  - has an inline script without its hash;
  - loads anything from another site.
- **CI and supply chain:**
  - Actions are pinned to the commits their tags pointed at today: checkout v4.4.0, setup-node v4.4.0, upload-pages-artifact v3.0.1, deploy-pages v4.0.5.
  - CI is `contents: read`. The Pages workflow grants nothing at workflow level and gives its job only what deployment needs.
  - Checkout no longer keeps the token.
  - CI runs `npm audit --audit-level=high`, the single-file build and `check:build`.
  - Dependabot is set to weekly, grouped updates for npm and github-actions.
- **Repository files:**
  - `SECURITY.md`: private vulnerability reporting, or a details-free issue.
  - `.github/CODEOWNERS`: @shehnshah55.
  - A PR template with the §0.2 source checklist.
  - Issue forms: Correction request, New data and Bug. Blank issues are off.
- **§10:** added "review from Code Owners" to the branch-protection item, and a 👤 item to enable private vulnerability reporting.

  A "How chosen" section lists each office and how it was filled. Ministers whose seat simply isn't recorded are **not** tagged: missing data is not evidence. 9 people are tagged now, all of them senators.

## 2026-10-02 · Phase 6: Keeping it fresh

Branch `launch/phase-6-freshness`, stacked on `launch/browser-tests` (PR #10). Task C in SS's order.

### What changed

- **`.github/workflows/freshness.yml`:** runs every Monday at 03:17 UTC, on each published release and on demand.
  1. It lists every source and law URL in the published data.
  2. It checks them with lychee, pinned to `lycheeverse/lychee-action` v2.9.0 (lychee 0.24.2).
  3. It writes a report and opens or updates **one** issue, "Records needing re-verification".

  It never edits data. Permissions are `contents: read` and `issues: write`, granted to this job only. All actions are pinned to SHAs.
- **`scripts/staleness.ts`** builds the report:
  - officeholders whose record is more than 90 days old, oldest first;
  - legal cases due for re-check;
  - broken links, each with the records that cite it.

  It is built from `publicGraph()`, so while legal cases are unpublished the public issue gives only their count, and their sources are not checked or listed.

  Two safeguards:
  - If most links fail in the same run, the report treats it as a network problem on the runner and doesn't list hundreds of false "broken" links.
  - Government sites that block automated checks are a known risk, so the report asks for every broken link to be confirmed by hand.
- **`docs/MONITORING.md`:** a design only, for agents that watch Cabinet Division, Establishment Division, provincial S&GAD, ECP, assembly, court and Gazette publications.
  - Agents propose; people decide. An agent may only open a pull request with a cited diff, and nothing is merged automatically.
  - Agents never touch legal cases, assets, family ties or Form 45 checks.
  - Each source starts in report-only mode.

### Verified

- **Run locally against today's data:** 208 URLs. The report lists 55 officeholder records more than 90 days old, and 4 legal cases due (count only). No case title or case-only source appears in the URL list or the report.
- **lychee 0.24.2 was run locally** (release binary) to capture its real JSON shape, which is now a test fixture. Its "cited by" lookup handles the trailing slash lychee adds to bare domains.

## 2026-10-21 · Audit: security, accessibility, correctness, comprehension, load speed

### Load speed

Measured over gzip, as GitHub Pages serves it, on a phone profile (Slow 4G: 1.6 Mbps, 150 ms; CPU slowed 4×).

| Home page | Before | After |
|---|---|---|
| Downloaded | 1,003 KB | 614 KB |
| Script (gzipped) | 628 KB | 246 KB |
| Content visible | 8.6 s | 4.5 s |
| Main-thread blocking | 3.2 s | 0.7 s |

- **The world atlas left the bundle.** The full Natural Earth atlas (224 KB gzipped) shipped to draw Pakistan and four neighbours, and the outline was cut on every visit. `scripts/build-basemap.ts` now cuts it once into `src/geo/basemap.json` (9.8 KB gzipped). `tests/basemap.test.ts` fails if the file drifts. The maps differ from before by anti-aliasing only (0.5% of pixels). The atlas and polygon libraries are now dev dependencies.
- **Cytoscape loads only when a graph scrolls into view** (`src/ui/graph-canvas.ts`, loaded on demand). It was 138 KB gzipped, plus a force layout of about 370 ms on desktop that ran on every page load.
- **The graph data is parsed with `JSON.parse`** instead of being evaluated as a JavaScript object literal.
- **Fonts declare a `unicode-range`**, so a page downloads only the faces whose characters it shows.
